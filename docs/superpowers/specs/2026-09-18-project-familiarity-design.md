# Project Familiarity（两套视图、一份数据）

Date: 2026-09-18  
Status: Spec (not implemented)  
Grill: [`.grill/project-familiarity.md`](../../../.grill/project-familiarity.md)  
Does not replace: [2026-09-15-durable-core-memory-design.md](./2026-09-15-durable-core-memory-design.md)

## 1. Goal

插件随长期开发越来越熟悉**这一个项目**。新手打开项目 Tab 就能动手；老手能顺着从建仓以来的主干看到「做了什么重要开发、改了什么」；新 Session 的 Agent 拿到与人同一份 briefing，再加上 Core 站立事实，像同一名从业者接着干。

熟悉的主体是 **人 + Agent 同一条开发线**，不是一份越堆越大的知识库，也不是聊天回放。

**Winning condition**

1. 未读过仓库的人，看第一屏四句话后知道改哪、卡在哪。  
2. 新 Session 不介绍项目，模型第一轮能点到 briefing 里的入口/关键文件，且不重开已结算决策。  
3. 「任务动态」能从 `init` 顺着 Session 主干走到现在；点开节点能看到人话摘要和文件证据。

## 2. Non-negotiables

- 一份 `.project-brain/`，不新造编年史文件、不把聊天原文入库。
- Durable Core 闸门全部保留：`admitMemory` 单写者、changelog 不进 Core、Core 硬顶 15 / ~800 token、禁止 Jaccard merge-and-drop。
- 人 Tab 与 Agent 注入的 briefing **同一组装函数、同一字段**；禁止两套文案各写各的。
- 挤占 token 时先截断 briefing 的「最近为什么」，**不截断、不静默丢 Core**。
- LLM **不得**编造 Session 之间的因果边。
- 架构过期不得假装确定。
- 向量检索仍不是续接主路径。
- 未初始化项目：不写记忆、不写假 timeline 节点、不注入。

## 3. Two views

| 视图 | 给谁 | 读什么 | 不读什么 |
| --- | --- | --- | --- |
| Briefing + Core | 人第一屏 + 每次 Agent 注入 | 见 §4、§5 | git 全量、dormant 全量、泳道全图、聊天 |
| 架构 Tab | 人（第二层） | `architecture.json` 分层/路径 | 不进第一屏、不整图注入 |
| 任务动态主干图 | 人（第二层） | 由 timeline/todo/memory **派生**的 Session 图 | 聊天、工具轨迹 |
| Git Tab | 人（证据） | 提交时间线 | 不当主史、不进注入 |
| `project_ask` | 人/Agent 按需 | Core + dormant（及既有 timeline 检索） | 不自动灌进每个 prompt |

## 4. First screen（项目 Tab / 概览）

只回答四句。多了的进其它 Tab。

| # | 问题 | 数据源 | 展示上限 |
| --- | --- | --- | --- |
| 1 | 这是什么 | `project.name` + 净化后 description（截断）+ 运行时技术栈 chip | description ≤ 300 字 |
| 2 | 从哪改 | 见 §4.1 | 入口 1 个优先 + 关键文件 ≤ 5 |
| 3 | 现在卡在哪 | `in_progress` 优先，否则最高优先级 pending TODO | ≤ 3 条 |
| 4 | 最近为什么 | 最新一条非空 `session_summary.summary`；否则最新 Core `decision` 的 title+一句 content | 摘要截断与注入共用预算 |

完整泳道、目录树、dormant、Git 全史、导入导出按钮保持现有能力，但 **不得挤掉这四句的主视野**。

### 4.1 「从哪改」

正常（架构未过期）：

- `project.entrypoints` 去重后最多 2 个  
- `architecture.keyFiles` 或等价字段（见现有 `architecture.json` 的关键文件列表）最多 5 个，路径相对仓库根  
- 可选：主运行路径 **第一步和最后一步** 的文件，计入 5 个名额，不画整条编号箭头

过期（§6）：不用旧泳道当真理。改为 scanner 入口 + `project.json` 已有 entrypoints；UI 与注入都带 `architectureStale: true` 及一句「架构可能过期」。

## 5. Shared briefing（注入 = 第一屏的 markdown 形态）

单一纯函数（建议名 `buildProjectBriefing(brain, options)`），产出：

```ts
{
  stale: boolean,
  purpose: string,          // 这是什么；scanner 占位符 Auto-generated by … 视同为空
  startHere: string[],      // 从哪改，相对路径（只进注入）
  stuck: { id, title, status, priority }[],   // 活跃待办，in_progress 优先，≤3
  recentWork: string,       // 最近做什么（可空）
  recentWorkSource: "session_summary" | "todo" | "none",
  recentWorkAt: number,     // 该摘要的 occurredAt；todo 兜底为 0，不许编时间
  recentWorkStale: boolean, // 超过 30 天
  markdown: string          // 人/Agent 共用的 markdown
}
```

`buildInjectionContext(brain)`：

```text
## Project Brain
### 这是什么 / ### 最近做什么 / ### 从哪改   ← briefing.markdown
### 活跃待办            ← briefing.stuck，空则整段不出现
### Core 记忆           ← 现有 isCoreMemory 全量，硬顶仍由 admit/housekeep 保证
### 项目记忆约定
```

人第一屏只看「这是什么 / 最近做什么」；「从哪改」与「活跃待办」只进注入。

**「最近做什么」必须带时间。** 不带时间的近况会骗人：LLM 关掉几周后，第一屏还在拿旧摘要冒充近况。markdown 后缀「N 天前」，超过 30 天写「N 天前，可能已过时」。todo 兜底没有可靠时间戳，就不显示时间。

**活跃待办单独成段。** 续接靠 TODO，既不能混进「最近做什么」（pending 待办不是最近做的事），也不能只在「记忆约定」里空口叮嘱。

`project_continue.data.injection` 必须与 injector `section.render` **字节级一致**（沿用 Durable Core 契约）。

Briefing 独立预算：`recentWork` 沿用现有 `SUMMARY_MAX_TOKENS = 400`。Core 预算仍是条目 cap，不是再截 briefing。

## 6. Stale architecture + two-tier refresh

在 `project.json` 或 `architecture.json` 记录：

- `architectureAnalyzedAt`  
- `architectureHeadFilesFingerprint`（相关文件集合的指纹，不必存全量 blob）

**过期判定：** 当前工作区相对上次架构分析，`architectureTriggerFiles`（§6.1）有变更。轻扫成功 **不** 清除过期；只有 LLM/本地架构重分析成功才清除。

### 6.1 触发文件（收紧现状）

现状 `architectureRelevantFiles()` 把 README 也算进去，**本 spec 要求拆开**：

| 函数 | 命中 | 用途 |
| --- | --- | --- |
| `sourceChangeFiles(files)` | 源码扩展名（现有 `SOURCE_EXTENSIONS`），排除 generated/vendor | 轻扫 |
| `architectureTriggerFiles(files, { changes, entrypoints })` | **结构化规则，不得硬编码任何仓库的具体路径**：① manifest（现有 `MANIFEST_NAMES`）与 `cordis.patch.yml`；② `project.json.entrypoints` 里声明的文件入口（`type: "script"` 的 npm 脚本不算）；③ 约定入口文件名 `index`·`main`·`app`·`server`·`mod`·`lib`·`__init__`·`__main__` + 源码扩展名；④ 源码文件的**增删**（`changes[].type` 为 `added`/`removed`）。**排除** README、CHANGELOG、lockfile、测试、generated/vendor，以及普通源码的「改内容」 | LLM/本地架构重分析 |

纯测试路径启发式：`/(^|\/)(?:test|tests|__tests__|spec|specs)(\/|$)/i` 或 `/\.(?:test|spec)\./i`。

「改一行 UI 就跑一次 LLM 架构」和「换个项目就永远不刷新架构」是同一个错误的两面：规则必须由 manifest / 声明入口 / 文件增删这类**结构信号**决定，不能靠列举某个仓库的目录名。宁可漏触发，也不要不可移植。

### 6.1.1 会话变更窗口

`files` 不再取 `HEAD vs HEAD~1`。`detectSessionChanges({ projectPath, sinceMs, now })`（`src/host/diff/session-window.js`）合并两路：

- 工作树中 mtime 落在 `(sinceMs, now]` 的文件——**未提交的改动也算**，非 git 项目同样可用；
- `committer` 时间落在窗口内的 commit（上限 30 个），逐个与 first parent 做 tree diff。

窗口起点 `sessionWindowStart(brain, now)` = 上次 `session_summary.occurredAt` > `project.lastScannedAt` > `project.createdAt` > 24 小时前，且最长只回看 14 天。输出 `changes: [{ path, type }]`，`type ∈ added | modified | removed`。

### 6.2 Session 结束（`summarizeOne` 之后）

顺序：git diff → 语义抽取/admit → 写 `session_summary` → housekeep → **刷新**（失败只打日志，不阻塞 disposed）。

1. `sourceChangeFiles` 非空 → `scanAndWrite(..., { architectureMode: "light" })`：只更新 `project.json` 扫描字段（入口、技术栈、语言），**保留**现有 `architecture.json`。  
2. `architectureTriggerFiles` 命中 → 再 `scanAndWrite(..., { architectureMode: "full" })`。  
3. **触发了就必须给出结论**：full 成功且 `architecture` 无 error → `architectureStale = false`（由 `scanAndWrite` 写入）；full 失败或架构带 error → 用 `markArchitectureStale(fs, policy, projectPath, true)` 显式置 `architectureStale = true`，只改标记不碰 `architecture.json`。轻扫不改该标记。

用户手动 `project_rescan` / 第一屏「重扫」= `architectureMode: "full"`。

## 7. `session_summary` 合同

写入 `timeline.jsonl`，`eventType: "session_summary"`。

**正文 `summary`：** 1–3 句，做什么重要的 + 为什么。禁止 changelog 体裁（「改了 N 个文件」、验收清单、patch 标题）。与 `isChangelogGenre` / `isActivityReport` 同一套否决；命中则 `summary` 置空并记 `summaryRejected: "changelog_genre"`。

**附件（可进节点展开，不进注入）：** `changedFiles` 最多 20 条相对路径（现有 detail 字符串不够用，本 spec 要求结构化字段 `files: string[]`）。

抽取失败或 transcript 太短：仍可写 timeline 行以便去重 `sessionId`，但 `summary` 为空。图与 briefing **视为无摘要**。

关会话没留下非空摘要、也没「记住」、也没 admit 成功：talk-only 回合在史上等于没发生。

## 8. Development chain graph

不新增 json 文件。每次 preview / RPC 由纯函数 `buildSessionGraph(brain)` 从已有 jsonl 派生。

### 8.1 节点

一个节点对应一次 `sessionId`。无 `sessionId` 的实质事件（`session_summary` / `todo` / `memory` / `memory_supersede`）按发生日合成 `day:YYYY-MM-DD` 桶，使旧时间线仍能成干。`init` 可合成 `sessionId: "init"`。`rescan` / `export` / `import` / `rollback` 不成节点。

**进入主干（`trunk: true`）当且仅当至少一条：**

- 非空且未 reject 的 `session_summary.summary`  
- 该桶关联的 git `files.length > 0`  
- 该桶有 TODO 状态变化，或非 changelog 体裁的 memory  
- 纯 changelog 体裁记忆、仅重扫/导入导出、空摘要且无文件：不进主干，计入 `collapsedEmptyCount`

节点展示：

- `label`：优先 `summary` 第一句（切句时保护 `v0.4.13` 这类版本号，不当句号）；否则该桶内非 changelog、非补丁体裁的 memory/todo 标题（去掉「新增记忆/待办」前缀）；否则 `代码有变更（无摘要）`（仅当有 files）。  
- `detail`：展开区正文。取摘要第一句之后的余句，否则取该桶记忆的 `content`；与 `label` 相同则为空，展开区不复写标题。**纯文本**：展开区不渲染 markdown，`##` / `**` / 反引号 / 列表 / 引用 / 链接语法一律剥掉（只去符号、不丢文字）。上限 900 字，优先在句末断开，真截断时结尾必须是 `…`；UI 侧可滚动，不做视觉截断。  
- `files`：最多 5 个展示，其余 `filesMore`  
- `occurredAt`：桶内**最后一次活动**时间（timeline 与 memory 统一口径，否则先后会错）  
- `sessionId`（日桶为 `day:YYYY-MM-DD`）

**补丁体裁判定：** 以版本号开头**且**后面是补丁/发布语气（patch / hotfix / fix / 修复 / 补丁 / 发版 / 验收 / 改动说明），或版本号后什么都没有。只看「开头是不是数字」会误杀 `2.0 版本规划`、`3.2 数据层重构`。

**禁止**用「改了 N 个文件」当 `label`（与 §7 一致）。无摘要仅有文件时用固定文案 `代码有变更（无摘要）`。

### 8.2 边

- **主干边：** 按 `occurredAt` 排序后相邻 trunk 节点 `kind: "time"`  
- **证据边** `kind: "evidence"`，仅三种：  
  1. 同一 `todo.id` 在 a 打开、在之后的 b 关闭。**只有「开 → 关」算因果**：把 done 事件也当起点，会在重复标记完成时连出假边。实现用 `todoId → 完成节点下标` 倒排索引，不做全对遍历。  
  2. `project_memory_supersede` / admit `supersedes` 连接新旧 memory 所属 session  
  3. `architectureMode: "full"` 的 rescan 事件，`triggerFiles` 与**紧邻的上一个** trunk 节点 `files` 有交集（不跨节点连远边）  

无证据则不要第二条边。不要 LLM 补边。

### 8.3 抽稀（默认全自动，不做手动里程碑）

trunk 节点 > 40：隐藏 `important: false` 的节点，**但保底显示最近 20 个**。只有摘要缺失、历史全靠记忆标题的项目，一次性藏光会让默认视图几乎空白，反而更像"断开"。其余进「展开全部」。节点本身不删。不按周合并（避免把因果边弄断）。手动钉版本节点 **本版不做**。

### 8.4 UI

升级现有 **任务动态** Tab：上半主干图（时间从左到右或从上到下），下半可保留 TODO 列表。Git Tab 不变。点节点：摘要全文 + 文件列表 + 跳 Git 不强制。

## 9. Out of scope

- 聊天原文 / 工具调用回放  
- LLM 项目编年史、无证据因果  
- 第一屏或注入塞满泳道/目录/全史  
- 跨项目联邦、再扩 AST、替代 Jira  
- 每轮对话一个图节点  
- 手动里程碑钉选（可后加）
